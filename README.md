# GAS RSS Digest

RSS/Atomの新着をGemini APIで日本語要約し、自分へメールするGoogle Apps Scriptです。
RSS取得先と送信内容はGoogleスプレッドシートで管理します。

これは新規に作成したGAS実装です。既存のNode.js教材のファイルを上書き・移植したものではありません。
GitHubはソース配布先、実行場所は各利用者のApps Scriptプロジェクトです。

対象バージョン：1.1.5

## 機能

- RSS 2.0 / Atom / RSS 1.0（RDF）の取得。
- `RSS設定`の有効な行から取得。情報源名・URL・取得上限を編集できます。
- Gemini APIキーをコードへ埋め込まず、スクリプトプロパティから取得。
- `メール履歴`に実際の件名・宛先・テキスト本文・HTML本文を保存。
- `記事履歴`に記事名・URL・要約・配信IDを保存。
- 成功したメールのURL一覧を使い、再送を防止。
- 同じプロジェクト内の手動実行とタイマー実行をロックで排他。
- 不確定な送信結果は自動再試行せず停止。送信前に止まったと確実に分かる場合は自動で取消（`CANCELLED`）。
- タイマー実行が停止したときは、送信先へ短い停止通知を送信（設定で無効化可）。
- 時間の安全上限に近づいたら、要約済みの記事だけで送信し、残りは次回へ。
- Geminiの回数制限対策として、呼び出し間隔の調整と429/5xxの再試行（最大3回）。
- Shift_JIS/EUC-JP等の日本語フィード、BOM付きフィード、`JST`表記の日付に対応。
- プレビューはAPIを利用しますが、メール送信・送信済み記録は行いません。

## 最初の設定

1. 自分用のGoogleスプレッドシートを新規作成します。既存資料とは分けてください。
2. スプレッドシートの「拡張機能 → Apps Script」を開きます。
3. `Code.gs`の全文をApps Scriptのコードへコピーします。
4. Apps Scriptの「プロジェクトの設定」でマニフェスト表示を有効にし、`appsscript.json`をコピーします。
5. 同じ設定画面の「スクリプト プロパティ」に、次の項目を登録します。

| プロパティ名 | 必須 | 設定値 |
| --- | --- | --- |
| `GEMINI_API_KEY` | 必須 | 自分のGemini APIキー |
| `GEMINI_MODEL` | 必須 | 自分のAPIで利用可能なテキスト生成モデルID。`models/`接頭辞は任意 |
| `SPREADSHEET_ID` | 任意 | 手順2のようにスプレッドシートから開いたApps Scriptなら不要です。スプレッドシートと別に作ったスクリプトで使う場合だけ、対象URLの `/d/` と次の `/` の間のIDを設定します |
| `GEMINI_THINKING_BUDGET` | 任意 | 思考（thinking）の上限トークン数。例：`0`で思考なし（対応モデルのみ）。応答時間とAPI使用量を抑えたいときに設定 |
| `GEMINI_THINKING_LEVEL` | 任意 | `minimal` / `low` / `medium` / `high`。思考レベル指定に対応したモデル用。`GEMINI_THINKING_BUDGET`とはどちらか一方だけ |

思考設定は未設定ならモデルの既定どおりです。モデルが対応しない値を指定するとGeminiが`GEMINI_HTTP_400`を返し、要約が失敗します。そのときは設定を消すか値を変えてください。

GASにはNode.jsの`process.env`と同じ環境変数はありません。本実装は、設定をソースから分ける目的でスクリプトプロパティを使います。キーをこのREADME、コード、シート、公開リポジトリへ書かないでください。モデル名は古い固定値を避けるため必須設定にしています。モデルの利用可否・料金は利用者がGoogle AI Studio等で確認してください。

6. 関数一覧から`setupSheets`を選んで実行し、自分のGoogleアカウントで権限を承認します。6つのシートが作られ、`メール履歴`の「状態」列には選択肢（プルダウン）が付きます。メール送信やタイマー登録はまだ行いません。
7. `配信設定`の「送信先」に本人のメールアドレスを1件入力します。その他の既定値は次のとおりです。

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| 最大記事数 | 5 | 1通に載せる記事数（1〜10） |
| 件名接頭辞 | 毎朝のRSS要約 | 件名の先頭 |
| 実行時刻 | 7 | 日本時間の時（0〜23） |
| 要約間隔秒 | 4 | Gemini呼び出しの最小間隔（0〜60秒）。429が多い場合は増やします |
| 停止通知 | TRUE | タイマー実行が停止したとき送信先へ通知するか |
8. `RSS設定`にフィードを登録します。例：

| 有効 | 情報源名 | RSS URL | 取得上限 |
| --- | --- | --- | --- |
| TRUE | 自分で選んだ情報源 | 利用条件を確認したRSS/Atomの絶対URL | 5 |

`有効`にはチェックボックスのTRUE、または文字列`TRUE`を指定します。通常のWebページではなくRSS/Atomを指定してください。初期状態に外部サイトは登録していません。

9. `previewDigest`を実行します。Gemini APIの利用が発生します。`メール履歴`の`PREVIEW`行で内容を確認してください。メールは送信しません。プレビューは送信済み扱いにならないため、繰り返すと再度要約します。
10. 宛先と内容を確認して、`sendDailyDigest`を手動実行します。実際に送信します。届いたメールと履歴を確認してください。
11. 問題なければ`installDailyTrigger`を1回実行します。以後毎日実行します。コードをコピーしただけでは自動配信は始まりません。

### 以前の版から1.1.5への更新

1. 旧コードの`removeDailyTrigger`を実行し、進行中の実行が終了したことを確認してから、`Code.gs`を全文置き換えます（`appsscript.json`は変更なし）。
2. `setupSheets`を1回実行します。既存データは消さず、`通知履歴`シートと不足している設定行を追加します。
3. `previewDigest`で動作を確認してから、`installDailyTrigger`で日次実行を再登録します。
4. `SPREADSHEET_ID`は設定したままで問題ありません。

手順2を忘れても要約配信は止まりません。ただし`通知履歴`シートがない間は停止通知・記録警告を送れず、毎回の実行履歴とメール履歴の詳細に「通知履歴シートがないため停止通知を送れません」と残ります。

### 日次トリガー

日次トリガーは設定した時の時間帯に動き、7:00ちょうどの配信を保証しません。時刻変更後は`installDailyTrigger`を再実行します。同じ利用者が作った`sendDailyDigest`用トリガーを置き換え、他の関数のトリガーは触りません。停止は`removeDailyTrigger`です。他の利用者が作成したトリガーは削除できないため、運用者は1人にしてください。

## 関数一覧

| 関数 | 外部API | メール | 用途 |
| --- | --- | --- | --- |
| `setupSheets` | なし | 送らない | 不足シート・列見出しの初期化 |
| `previewDigest` | RSS・Gemini | 送らない | 本文プレビューをシートへ保存 |
| `sendDailyDigest` | RSS・Gemini | 送る（タイマー実行の停止時は停止通知も） | 手動確認・日次実行 |
| `installDailyTrigger` | なし | 送らない | 日次実行を登録 |
| `removeDailyTrigger` | なし | 送らない | 日次実行を停止 |
| `diagnoseFeeds` | RSSのみ | 送らない | RSSごとの取得結果を実行ログに表示（Gemini・シート書込みなし） |

`setupSheets`は既存行を削除しません。列名や順番が違うシートは上書きせずエラーにします。既存データの列を勝手に並べ替えないでください。

## 要約の対象

Web記事の全文を取得せず、RSSに含まれる本文・抜粋の先頭最大3,000文字を要約します。フィードが見出ししか返さない場合、内容を補って記事全文の要約にはしません。出典リンクと「RSS抜粋のAI要約」という説明をメールへ入れます。AIの出力に事実誤認がないことは保証しません。

プロンプトは`Code.gs`の`summarizeDigestArticle_`にあります。モデルに外部ツールを渡さず、フィード中の命令を作業指示として扱わないよう指示します。要約失敗記事は送信せず、送信済みにもしません。次回取得範囲に残っている場合は再び候補になります。

Geminiへの呼び出しは「要約間隔秒」以上の間隔を空けます。429（回数制限）と5xxは、応答に再試行待ち時間（RetryInfo）があれば指定秒数以上、なければ5秒→15秒待って、1記事あたり最大3回まで試します。指定待機が60秒を超えるか、待ち時間（API指定またはバックオフ）が残り時間に収まらない場合、待ち時間を短縮せず、その回の残りのGemini呼び出しを見送ります。要約済み分だけを送信し、残りは次回候補です。最終試行の429/5xxでもRetryInfoが返された場合は、待機秒数の長短にかかわらず、その回の後続記事を次回へ延期します。完了済みの要約は送信します。警告文は「API指定の待機（N秒）を今回実施できないため」と「HTTP 503後の再試行待機が残り時間に収まらないため」のように理由を分けて残します。

要約の途中で時間の安全上限（約4分から送信用の余裕30秒を引いた時点）に達した場合は、要約済みの記事だけで1通送り、残りは次回候補にします。

フィードの文字コードは、BOM → HTTPヘッダーのcharset → XML宣言のencoding → UTF-8の順に判定します。`Shift_JIS`は上位互換のCP932（windows-31j）として読みます。

有効RSSは最大20件、情報源ごとの取得上限は1〜30件、1通は最大10記事です。全取得先の候補を公開日時順で選びます。情報源の偏りを均等化する機能や、フィードから消えた過去記事の回収はありません。記事URLのフラグメントを除いて重複判定します。別URL・追跡パラメータ付きURL・URL変更は別記事となる場合があります。

## 保存と再開

送信前に本文を`PREPARED`で保存 → 記事を保存 → `SENDING`を保存 → メール送信 → 正常終了で`SENT`に更新します。`SENT`はMailAppの送信処理が正常終了した状態で、受信箱への到着保証ではありません。

メール送信とシート更新を1つのトランザクションにはできません。途中停止・タイムアウト・送信例外では`PREPARED` / `SENDING` / `UNKNOWN`が残ることがあります。残っている間、実送信を停止します。自動的に送信し直すと重複するおそれがあるためです。復旧は[docs/RECOVERY.md](docs/RECOVERY.md)を参照してください。

ただし、送信要求の前（記事履歴の保存中・時間上限など）に例外で止まった場合は、未送信が確実なので自動で`CANCELLED`にし、次回の配信を妨げません。`CANCELLED`の記録自体に失敗した場合や、GASの実行時間上限で強制終了した場合は`PREPARED`が残ります。

タイマー実行が停止したときは、送信先へ「（件名接頭辞） 停止通知 日時」という短いメールを送ります。未確定の行が残っている間は毎日届きます。`通知履歴`に通知ID・関連実行ID・宛先・件名・本文・送信日時・状態を保存します。本文の保存に失敗した場合、通知を送信しません。`通知履歴`シートがない場合も送信せず、実行履歴に記録します。通知履歴は記事の重複判定と分離しており、通知の未確定状態だけで要約配信を止めることはありません。同じ通知を自動再試行しませんが、停止が続く場合は翌日の別通知を試みます。

この通知には配信IDを入れていないため、未確定配信の受信確認（配信IDでの検索）と混同しません。手動実行での停止は画面にエラーが出るため通知しません。

要約メールが送信済みで`SENT`も記録でき、実行履歴の保存だけが失敗した場合は、結果を`SENT`のまま返し、戻り値の警告に残します。メールは送りません（配信は完了しており、メール履歴に記録があるため）。送信処理後にメール履歴の確定（`SENT`記録）が失敗した場合は「記録警告」を通知し、再送を促しません。「停止通知」をFALSEにすると記録警告の通知も無効になります。

履歴シートの文字列は「書式なしテキスト」として保存します。題名の`2026`が数値に、公開日時が日付に自動変換されることを防ぐためです。重複判定のときは`メール履歴`の状態〜記事キーJSONの列だけを読み、本文列は読みません。

履歴を削除すると、その履歴にあるURLの重複判定も失われます。初版では自動削除・アーカイブ機能を設けていません。履歴が大きくなった場合は、保全方法と重複判定の引継ぎを決めてから整理してください。保存セルの上限に近づく大きな本文は切り捨てず、保存時に停止します。

## 権限と公開範囲

マニフェストはシート編集、外部HTTP通信、メール送信、トリガー管理を要求します。Gmailの受信箱を読む権限は要求しません。送信元はトリガーを作った利用者です。

スクリプトプロパティはプロジェクトの編集者からキーを隔離する保管庫ではありません。シートに紐づくスクリプトはシートの共有権限の影響を受けます。自分用のシートとスクリプトを使い、配布時はGitHub上のコードを各自がコピーする方式を推奨します。

GitHubに公開するのはソース・空の設定例・説明書・テストです。APIキー、シートID、送信先、実際のメール本文・記事履歴は各利用者の環境だけに保存します。GAS実行時にキーをソースへ追記しないでください。

## 制限と費用

URL取得（UrlFetchApp）の1日の回数上限は、スクリプトごとではなくGoogleアカウント全体で数えます。同じアカウントで他のスクリプトが多く取得していると、このスクリプトのRSS取得やGemini呼び出しも失敗します。その場合は`URLFETCH_DAILY_QUOTA`として停止し（要約の途中なら要約済み分だけ送信）、上限は24時間以内に回復します。

Apps Scriptの通常実行は1回6分です。本コードは約4分を安全上限として工程間で確認しますが、個々のHTTP通信が長く待つ場合の終了時刻は保証しません。Gemini・RSSへの通信、メール送信、トリガーにはそれぞれ利用条件・上限があります。Geminiの429/5xx応答だけ最大2回再試行し、メールは再試行しません。停止通知は1回につき1通のメール送信枠を使います。API側の課金・無料枠は別途確認してください。

## 開発用テスト

GASへの導入にNode.js/npmは不要です。手元でのテストだけNode.js 20以上を使います。

```bash
npm test
```

テストはGASサービスをモック化して、履歴と重複防止・プレビュー・途中停止時の挙動・停止通知・再試行・文字コード判定を確認します。変更点は[CHANGELOG.md](CHANGELOG.md)にあります。実API・実シート・実メール・GASのXMLパーサー・タイマーはこのテストでは検証しません。確認結果は[docs/VALIDATION.md](docs/VALIDATION.md)にあります。
